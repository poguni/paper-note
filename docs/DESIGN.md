# 페이퍼노트(Paper Note) DESIGN.md

페이퍼노트의 화면 디자인을 구현하기 위한 문서입니다. 기능과 동작은 PRD를 따르고, 이 문서는 **보이는 모양**만 다룹니다.
함께 전달하는 시안 파일은 다음 두 개입니다. 값이 헷갈리면 시안 HTML이 기준입니다.

- `paper-note-design1-academic.html` : 테마 `academic` (학술, 인디고와 와인)
- `paper-note-design3-education.html` : 테마 `education` (교육용, 따뜻한 서재)

## 1. 원칙

1. 한 앱에 두 테마를 넣고, 사용자가 설정에서 고릅니다. 기본값은 `academic`입니다.
2. **HTML 구조는 하나**입니다. 테마마다 바뀌는 것은 CSS 변수(색, 글꼴, 모서리, 여백)와 화면 배치 규칙뿐입니다. 테마별로 컴포넌트를 따로 만들지 않습니다.
3. 색과 글꼴 값은 CSS에 직접 쓰지 않고 항상 변수로 씁니다.
4. 화면은 1920×1080에서 가로 전체를 씁니다. 가운데에만 내용이 몰리는 배치는 쓰지 않습니다. (로그인과 승인 대기 화면은 예외입니다.)
5. 본문과 작은 글씨도 읽을 수 있어야 합니다. 일반 글씨는 명암비 4.5:1 이상, 글자 크기는 12px 이상으로 합니다. (시안 1의 11.5px 글씨는 12px으로 올립니다.)
6. 새 화면을 만들 때마다 두 테마에서 모두 확인합니다.

## 2. 테마 적용 방식

```html
<html lang="ko" data-theme="academic">
```

- 테마는 `<html>`의 `data-theme` 속성(`academic` | `education`)으로 바꿉니다.
- 선택값은 `localStorage`의 `pn_theme` 키에 저장합니다. 테마는 민감 정보가 아닙니다.
- 첫 화면이 깜빡이지 않도록 `<head>` 맨 위의 작은 인라인 스크립트가 저장된 값을 읽어 `data-theme`를 먼저 적용합니다. 저장값이 없거나 잘못되었으면 `academic`입니다.
- 테마 선택은 두 곳에 둡니다. 설정 화면의 선택 목록(미리보기 포함)과 **왼쪽 메뉴 아래의 빠른 전환 버튼**입니다. (academic에는 상단 막대가 없어서 두 테마에 모두 보이는 사이드바에 둡니다.) 미리보기는 `data-theme-scope` 속성이 그 테마의 토큰을 켜서 칠합니다.
- 글꼴 파일은 선택된 테마의 것만 불러옵니다. 테마를 바꿀 때 해당 글꼴 `<link>`를 추가합니다. 한글 웹폰트는 용량이 커서 둘 다 항상 받지 않습니다.
- 선택한 글꼴을 아직 받지 못한 동안에는 아래 대체 글꼴 순서로 보입니다.

### 3.2 칩과 타일 (의미 단위로 정의)

칩은 색 이름이 아니라 **의미**로 부릅니다. 테마마다 색만 다릅니다.

| 토큰 (배경 / 글씨) | academic | education | 의미 |
|---|---|---|---|
| `--chip-source-bg` / `-text` | `#F4E1E5` / `#7A2535` | `#DFE8F0` / `#3D5C78` | 출처 (arXiv) |
| `--chip-source2-bg` / `-text` | `#F3E9D2` / `#6F4E12` | `#F8EBC8` / `#7A5A12` | 출처 (Semantic Scholar) |
| `--chip-pdf-bg` / `-text` | `#E9EDF8` / `#1E2A4A` | `#E5EDDD` / `#476345` | PDF 있음 |
| `--chip-saved-bg` / `-text` | `#E3EEEF` / `#1F5559` | `#F6DDD2` / `#9C3F28` | 저장됨 |

academic 칩은 **시안 1을 기준**으로 정했습니다. 시안 1에서 arXiv 칩은 와인, 상세 패널의 저장됨 칩은 청록입니다. 시안 1에는 "PDF 있음" 칩이 없어서, 저장됨 칩과 같은 청록이 되지 않도록 인디고 계열(`--bg-selected`와 같은 색 + `--text`)을 새로 정했습니다. 출처(Semantic Scholar) 칩은 시안 1에 없으므로 금색(`#F3E9D2` / `#6F4E12`, 시안의 난이도 칩 색)을 그대로 씁니다. education 칩은 시안 3과 같아 바뀐 것이 없습니다.

구조화 요약 타일 4개(연구 목적, 방법, 결과, 한계)는 `--tile-purpose`, `--tile-method`, `--tile-result`, `--tile-limit` 배경·글씨 토큰을 둡니다.

- academic: 타일 배경은 `#F6F6F2`(`--bg-app`과 같은 색), 테두리 1px `#E4E3DC`, 모서리 8px입니다. 네 타일이 모두 같은 모양이고, 항목 이름(12px, 굵게, 자간 1px)만 `--accent` 색입니다. 색 면으로 구분하지 않습니다.
- education: 목적 `#E5EDDD`(글씨 `#476345`), 방법 `#DFE8F0`(`#3D5C78`), 결과 `#F6DDD2`(`#9C3F28`), 한계 `#F3E8D4`(`#6B5A4C`)

3줄 요약: academic은 상자 없이 제목(명조 18px)과 번호 목록입니다. 번호는 명조 18px 굵게, 색은 `--accent`입니다. education은 `#F8EBC8` 상자(제목 글씨 `#7A5A12`)에 ①②③ 문장을 넣습니다.

## 4. 화면 배치 (1920×1080)

두 테마의 HTML은 같고, 배치만 다릅니다. `body`에 `display: grid`와 `grid-template-areas`를 테마별로 지정합니다.

### 4.1 academic: 3열

```
| 사이드바 256 | 검색 결과 460 | 논문 상세 560 | 오른쪽 열 (나머지, 약 556) |
```

- 사이드바: 로고, 메뉴(검색, 내 서재, 설정), 프리셋 7개와 "+ 프리셋 추가", 맨 아래 API 키 상태 상자
- 맨 위 가로 막대(높이 72): 제목, 검색창, 출처 체크박스 2개, 모델 선택, 검색 버튼
- 가로 막대 바로 아래에 검색 필터 줄(높이 48, 접을 수 있음). 시안에 없으므로 5.9를 따릅니다.
- 오른쪽 열: 초록 번역, 용어 사전, 통계 상세(통계 분석 모드일 때), 바이브 코딩 아이디어 카드. 내용이 길면 열 안에서 세로로 스크롤합니다.
- 상단 4단계 표시는 없습니다.

### 4.2 education: 상단 막대 + 2열

```
| 상단 막대 96 (로고 / 4단계 표시 / API 키와 모델) |
| 사이드바 288 | 검색 결과 600 | 논문 상세 (나머지, 약 944) |
```

- 4단계 표시: 검색 → 저장 → 분석 → 내 서재. 완료 단계는 `--ok` 색 원과 체크, 현재 단계는 `--accent` 원, 앞으로 할 단계는 테두리만 있는 원입니다. 색만으로 알리지 않도록 번호와 ✓를 쓰고, 스크린리더에는 "(완료)", "(현재 단계)"를 읽어 줍니다.
- 상단 막대의 오른쪽에는 API 키 요약(눌러서 입력)과 **분석 모델 선택**이 있습니다. 모델 선택은 academic에서는 검색 막대에 있고, education으로 바꾸면 같은 요소가 상단 막대로 옮겨집니다.
- 좁은 화면(1080px 이하)에서는 상단 막대를 고정하지 않고 맨 위 줄로 두며, 내용이 길면 줄이 바뀝니다.
- 논문 상세 안에서 왼쪽에는 3줄 요약과 구조화 요약을, 오른쪽에는 초록 번역과 용어 사전을 나란히 둡니다. 맨 아래에 PDF 드롭존(290px)과 아이디어 리본을 놓습니다.
- 프리셋 번호는 숫자 앞의 작은 색 점(10px)으로 구분합니다.
- 검색창 아래 줄에는 출처 칩 2개와 결과 건수·정렬 선택을 두고, 그 아래 한 줄에 필터 3개(기간, 최소 인용수, 검색 개수)를 둡니다. 시안에 없으므로 5.9와 5.10을 따릅니다.
- 통계 상세는 오른쪽 열의 용어 사전 자리에 **"용어 사전 | 통계 상세" 탭**으로 넣어, 1080 높이에서 넘치지 않게 합니다. 통계 분석 모드가 꺼져 있으면 탭을 보이지 않습니다.

### 4.3 두 배치에서 공통인 규칙

- 선택된 논문의 정보는 항상 같은 순서로 나옵니다: 제목, 저자·연도·학술지, 상태 칩, 초록 단계/본문 단계 전환, 3줄 요약, 구조화 요약, 초록 번역, 용어 사전, 통계 상세(통계 분석 모드일 때만), PDF 드롭존, 바이브 코딩 아이디어.
- "4단계 표시"는 두 테마가 같은 현재 단계 값을 씁니다. academic에서는 보이지 않을 뿐입니다. 단계 값은 앱 상태에서 계산합니다. (논문을 고르지 않음 → 검색, 저장함 → 저장, 분석 결과가 있음 → 분석, 서재 화면 → 내 서재) 현재 화면에 열려 있는 논문만 기준으로 하고(다른 화면의 상세는 세지 않음), 열린 논문이 저장되지 않았으면 아직 검색 단계이며, 저장하지 않고 분석했어도 분석 단계입니다. 설정 화면에서는 어느 단계도 현재가 아닙니다.
- 1366px 같은 작은 화면에서는 열 폭을 줄이고 오른쪽 열을 상세 아래로 내립니다. 1920 기준 시안 외에는 시안이 없으므로 구현하면서 정합니다.

## 5. 컴포넌트

### 5.1 검색 결과 카드
- 높이 약 148~160px, 제목(2줄까지) → 저자와 연도 → 칩 줄(출처, PDF 있음, 저장됨)
- 인용수는 "인용 1,234" 모양의 중립 칩(`--bg-app` 배경, `--text-muted` 글씨, `--border` 테두리)으로 보여 줍니다. 확인하지 못했으면 "인용수 미확인"으로 씁니다. academic은 출처 칩 오른쪽에, education은 칩 줄 맨 끝에 둡니다.
- academic은 시안 1처럼 출처 칩을 저자 줄 끝에 두고, 아래에 버튼 줄(분석 보기 또는 초록 분석 / 저장 또는 저장됨 ✓ / 원문 PDF 열기)을 둡니다. "저장됨 ✓" 버튼은 `--accent-soft` 배경, `--accent` 테두리, `--accent-strong` 글씨입니다. education은 칩 줄만 두고 동작은 상세 패널에서 합니다.
- 선택됨: `--bg-selected` 배경 + 2px `--accent`(education) 또는 1.5px `--text`(academic) 테두리
- 저장된 논문은 오른쪽 위에 ★ 표시(`--accent`)와 "저장됨" 칩
- 호버: 테두리를 `--accent`로 바꿉니다. 포커스: 2px 윤곽선(`outline`)을 반드시 보이게 합니다.

### 5.2 프리셋 버튼
- 번호와 이름. 활성 프리셋은 `--sidebar-active-bg`
- "+ 프리셋 추가"는 점선 테두리 버튼
- 프리셋은 사용자가 추가, 수정, 삭제, 순서 변경을 할 수 있습니다. (PRD의 F11)

### 5.3 초록 단계 / 본문 단계 전환
- 두 칸짜리 분할 버튼. 활성 칸은 `--accent` 배경 + `--accent-on` 글씨
- 본문 단계는 PDF를 끌어다 놓기 전에는 비활성 표시와 안내 문구를 보여 줍니다.
- 분할 버튼 옆에 "통계 분석 모드" 체크박스(스위치 모양 금지, 글씨가 있는 체크박스)를 둡니다. 켜면 예상 비용에 통계 상세 분량을 더해 보여 줍니다.

### 5.4 구조화 요약
- 항목 4개: 연구 목적, 방법, 결과, 한계
- 값이 없을 때 문구는 정확히 **"초록에 언급 없음 · 본문 단계에서 확인"**입니다. 이 글씨는 `--text-subtle`로 씁니다.

### 5.5 번역, 용어 사전, 바이브 코딩 아이디어
- 초록 번역: 오른쪽 위에 모델 이름과 예상 비용("약 1센트")을 작게 표시
- 용어 사전: 한국어 용어(굵게)와 영어 원문(작게)을 2열 격자로
- 바이브 코딩 아이디어 카드: 이름, 한 줄 설명, 근거, 핵심 기능 3개, 난이도, 단일 HTML 가능 여부, 첫 프롬프트와 복사 버튼.
  - academic: 흰 카드(모서리 12px, 테두리 `--border`). 맨 위 작은 제목은 `--accent` 12px 굵게. 난이도 칩은 금색 계열(`#F3E9D2` / `#6F4E12`), "단일 HTML 가능" 칩은 청록 계열(`#E3EEEF` / `#1F5559`). 첫 프롬프트는 `#F1F1EC` 상자에 넣고, 오른쪽에 "프롬프트 복사" 버튼(높이 30px, 테두리 `#BFC3D2`)을 둡니다.
  - education: `#F6DDD2` 리본(높이 약 200px). "바이브 코딩 아이디어" 알약 칩은 `--accent` 배경 + 흰 글씨, 이름은 `--font-heading` 25px(`#7A2F1B`), "첫 프롬프트 복사" 버튼은 `#9C3F28` 배경입니다.

### 5.6 PDF 드롭존
- 점선 테두리, 위쪽 화살표 아이콘, 문구 "PDF를 끌어다 놓으면 본문 분석을 시작해요"
- 끌어 올 때: 테두리와 배경을 `--accent-soft`로 바꿉니다.
- 처리 중, 완료, 실패 상태를 각각 문구로 구분합니다.

### 5.7 API 키 상태
- 입력됨: `--ok` 점 + "입력됨" + "탭을 닫으면 삭제됩니다"
- 입력 전: 빈 점 + "키를 입력하세요" + 입력창 열기 버튼
- 계정: 로그인한 이메일과 "로그아웃" 텍스트 버튼을 사이드바 맨 아래, API 키 상자(academic) 또는 "알아 두세요" 상자(education) 바로 위에 둡니다. 이메일이 길면 말줄임으로 줄입니다.

### 5.8 버튼 공통
- 주 버튼: 높이 52px(검색 막대), `--accent` 배경, 굵은 글씨(education은 `--font-heading`)
- 보조 버튼: 흰 배경 + `--border-input` 테두리
- 눌림 상태는 배경을 한 단계 진하게 합니다. 비활성은 불투명도 0.5입니다.

### 5.9 검색 필터 줄

시안에 없는 컴포넌트입니다. 선택지와 기본값은 PRD "논문 검색"을 따릅니다.

- 컨트롤: 기간, 최소 인용수, 검색 개수(각각 `<select>`), "인용수 미확인 포함" 체크박스, "필터 초기화" 보조 버튼
- 키보드와 화면낭독기가 그대로 되도록 기본 `<select>`를 쓰고 토큰으로만 꾸밉니다. 높이 40px, 배경 `--bg-surface`, 테두리 `--border-input`, 모서리 `--radius-md`, 글씨 `--fs-small`입니다.
- 기본값이 아닌 값을 고르면 해당 컨트롤의 테두리를 `--accent`로 바꾸고, 줄 끝에 "필터 N개 적용 중" 글씨를 보여 줍니다. (색만으로 구분하지 않습니다.)
- "인용수 미확인 포함"은 최소 인용수가 "제한 없음"이 아닐 때만 켤 수 있습니다.
- academic: 가로 막대 아래 한 줄. "필터 ▾" 버튼으로 접고 펼 수 있고, 접어도 적용 중인 필터 수는 보입니다.
- education: 출처 칩 줄 아래에 알약(`--radius-pill`) 모양 컨트롤로 둡니다. 600px 안에 들어가지 않으면 두 줄로 나눕니다.
- 필터를 바꾼 뒤 "검색"을 눌러야 적용됩니다. 값이 바뀌었는데 아직 적용 전이면 검색 버튼 옆에 "필터 변경됨" 글씨를 보여 줍니다.
- 결과 0건: 빈 상태 문구와 "필터 해제" 버튼을 보여 줍니다. 필터 때문에 비었을 때는 "조건을 완화해 보세요"라고 안내합니다.

### 5.10 정렬 선택

- 결과 열 머리글 오른쪽의 `<select>` ("정렬: 관련도"). 기준 8개는 PRD "검색 결과 정렬"을 따르고, 서재에서는 "저장일순"이 추가됩니다.
- 바꾸면 호출 없이 바로 다시 늘어놓습니다. 시작값은 프리셋의 기본 정렬입니다.
- academic: 결과 열 머리글 왼쪽은 "검색 결과" 제목과 "통계 · 24건"(`--fs-small`), 오른쪽은 정렬 선택입니다. 시안 1의 "프리셋 통계 · 최신순" 자리를 대체합니다.
- education: "검색 결과 24건" 오른쪽 끝에 정렬 선택을 둡니다.

### 5.11 통계 상세 카드

- 보이는 조건: 본문 단계이고, 통계 분석 모드가 켜져 있고, 결과의 `is_statistical`이 true일 때입니다.
- 항목 6개: 모형, 가정, 추정 방법, 사용 소프트웨어, 표본·자료, 적합도 지수. 항목 이름은 구조화 요약 타일과 같은 방식으로 씁니다. (academic은 `--accent` 12px 굵게 자간 1px, education은 `--font-heading`.) 값이 없으면 "본문에 언급 없음"을 `--text-subtle`로 씁니다.
- Python 재현 코드 뼈대: `--font-mono` 코드 상자(배경 academic `#F1F1EC`, education `#F3E8D4`, 가로 스크롤 허용), 오른쪽 위에 "코드 복사" 보조 버튼을 둡니다.
- 코드 상자 위에는 "AI 생성 초안 · 논문의 코드가 아닙니다" 칩(`--chip-source2-*`, 금색)을 항상 붙입니다. 이 칩은 숨길 수 없습니다.
- 위치: academic은 오른쪽 열의 용어 사전 아래 카드, education은 오른쪽 열의 "용어 사전 | 통계 상세" 탭입니다.
- 카드 모양은 같은 테마의 용어 사전 카드와 같게 합니다. 새 색은 쓰지 않습니다.

### 5.12 스플래시와 로그인

시안이 없고 스플래시 이미지는 따로 만듭니다. **스플래시와 로그인은 한 화면으로 확정**했습니다(2026-10-06). 이미지가 준비되기 전에는 이미지 없이 앱 이름 글씨로 된 임시 배경을 쓰고, 이미지가 생기면 배경만 교체합니다.

- 한 화면으로 구성합니다. 배경은 별도 제작한 스플래시 이미지(앱 제목과 빈 공간만 있는 이미지)이고, 아래쪽 빈 공간에 로그인 카드를 올립니다. 이미 로그인된 승인 계정은 카드 없이 로고만 약 1초 보이고 바로 앱으로 넘어갑니다(버튼은 없습니다). 로그인 직후에는 이 스플래시를 건너뜁니다.
- 로그인 카드: 이메일, 비밀번호(보이기·숨기기 버튼, "8자 이상" 안내), "로그인" 주 버튼, "회원가입" 텍스트 링크. 카드는 이미지 위에서 읽히도록 불투명하게 하고 `--bg-surface`, `--border`, `--radius-lg`, `--pad-panel`을 씁니다.
- 회원가입은 같은 카드 안에서 전환합니다. 이메일, 비밀번호, 비밀번호 확인, "가입 신청" 버튼입니다. 가입이 접수되면 "가입 신청이 접수되었어요. 관리자가 승인하면 로그인할 수 있습니다."를 보여 줍니다. 인증 메일은 가지 않습니다.
- 입력창에는 `<label>`을 연결하고, 포커스 윤곽선을 보이게 합니다. 오류는 입력창 아래에 글씨와 아이콘으로 보여 주고(`--accent-strong`), `aria-live`로 읽히게 합니다. 예: "이메일 또는 비밀번호가 맞지 않습니다", "비밀번호는 8자 이상이어야 합니다".
- 로그인 화면에는 테마 전환 버튼을 두지 않습니다. 마지막으로 고른 테마가 적용되고, 저장값이 없으면 academic입니다.

### 5.13 승인 대기 화면

- 로그인했지만 승인되지 않은 계정에게 보입니다. 화면 가운데의 카드 하나로 구성합니다. (원칙 4의 예외)
- pending: "승인을 기다리고 있어요. 관리자가 승인하면 사용할 수 있습니다." + "상태 새로고침" 주 버튼 + "로그아웃" 보조 버튼
- rejected: "가입이 승인되지 않았습니다." + "로그아웃" 보조 버튼
- 이 화면에서는 검색, 서재, 설정 메뉴를 보여 주지 않습니다.

### 5.15 분석 결과 비교 (F16)

- 같은 논문에서 같은 단계(초록 또는 본문)의 분석 결과가 2건 이상일 때, "저장된 결과" 선택 옆에 "결과 비교" 버튼이 나옵니다.
- 넓은 대화상자(최대 1120px)로 열리고, Esc나 바깥을 누르거나 "닫기"로 닫습니다. 닫으면 포커스가 버튼으로 돌아옵니다.
- 맨 위에서 왼쪽과 오른쪽에 볼 결과를 각각 고릅니다. 처음에는 가장 새 결과와, 그것과 다른 모델이 만든 가장 새 결과(없으면 그다음 결과)입니다.
- 각 칸의 머리에는 모델 이름, 만든 시각, 비용을 보여 줍니다. 비용은 이번 화면에서 만든 결과만 알 수 있고 저장된 결과는 "기록 없음"입니다(DB에는 AI 결과만 저장).
- 비교 항목: 3줄 요약, 초록 번역(초록 단계) 또는 구조화 요약 4항목·섹션별 번역·통계 상세·앱 아이디어(본문 단계), 용어 사전, 용어 겹침(공통 개수와 한쪽에만 있는 개수).
- 좁은 화면(760px 이하)에서는 두 칸이 위아래로 쌓입니다.

### 5.14 가입 승인 목록 (관리자 전용)

- 설정 화면 안의 구역입니다. 관리자가 아니면 구역과 메뉴 표시를 모두 숨깁니다.
- 표 열: 이메일, 신청일, 상태 칩, "승인"과 "거절" 버튼. 상태 칩은 pending이 `--chip-source2-*`(금색), approved가 `--chip-saved-*`, rejected가 `--bg-app` 배경에 `--text-muted` 글씨입니다. 칩에는 항상 글씨를 씁니다.
- 승인 대기 건수는 설정 메뉴 옆에 "대기 2"처럼 글씨가 있는 배지로 보여 줍니다.
- 상태는 나중에 다시 바꿀 수 있습니다. 승인, 거절 직후에는 결과를 한 줄로 알려 줍니다.

### 5.16 빈 상태, 오류, 로딩의 공통 규칙

- 오류 상자는 ⚠ 기호와 글씨를 함께 씁니다(색만으로 알리지 않음). 네트워크·서버 오류에는 "다시 시도" 버튼을 둡니다.
- 데이터베이스 오류 문장은 "(한 일)에 실패했습니다"로 통일합니다. 예: "서재 불러오기에 실패했습니다. 잠시 뒤에 다시 시도하세요."
- "목록이 비었음"과 "목록을 읽지 못했음"은 다르게 알립니다. 읽지 못한 목록은 "없습니다"라고 말하지 않고, 그 목록에 새로 추가하는 일은 막습니다.
- 목록이 비면 이유와 다음 행동을 알려 줍니다(예: 서재가 비었으면 "검색하러 가기").

## 6. 아이콘

- 선 아이콘(stroke) 24px 격자, 선 두께 1.8, 둥근 끝. 시안의 인라인 SVG를 그대로 재사용합니다.
- 색은 `currentColor`로 두어 테마 색을 따라가게 합니다.

## 7. 접근성 확인 목록

- 흰 글씨 위 `--accent`: academic `#8F2D3F` 대비 약 8:1, education `#C0503A` 대비 약 4.7:1
- 연한 배경 위 글씨(`--accent-strong` 등)는 4.5:1 이상이어야 합니다. 값을 바꾸면 명암비를 다시 계산합니다.
- 색만으로 뜻을 전달하지 않습니다. 칩은 항상 글씨가 있고, 저장 상태는 ★와 글씨를 함께 씁니다.
- 모든 버튼과 링크는 키보드로 접근되고 포커스가 보여야 합니다.
- 페이지 맨 앞에 "본문으로 건너뛰기" 링크를 둡니다. 평소에는 화면 밖에 있다가 키보드 포커스를 받으면 나타나고, 누르면 본문에 포커스를 옮깁니다(주소의 해시가 화면 이름이라 링크로 이동하지 않습니다).
- 배경 이미지 위의 글씨(로그인 첫 화면)는 사이드바 색 토큰이 아니라 스플래시 전용 토큰(`--on-splash`, `--on-splash-muted`, 배경 `--splash-bg`)을 씁니다. 이미지가 두 테마 모두 어두운 남색이라 값이 같고, 명암비 테스트에 들어 있습니다.
- 화면의 구역은 이름 있는 랜드마크로 둡니다: 로그인 화면은 `main`, 앱은 `main#main-content`, 사이드바는 `aside`. 본문 안의 오른쪽 열은 `aside`가 아니라 이름 있는 `section`입니다(랜드마크 중첩 방지).
- 한글 글꼴이 로드되지 않았을 때를 대비해 `--font-body` 맨 뒤에 `'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`를 이어 붙입니다.

## 8. 구현 순서 제안

1. `:root` 토큰 파일(`theme-academic.css`, `theme-education.css`)과 공통 컴포넌트 CSS를 나눠 만듭니다. (단일 HTML로 배포하더라도 소스는 이렇게 나눕니다.)
2. 시안 1을 기준으로 컴포넌트를 먼저 구현하고, 색과 글꼴을 모두 변수로 바꿉니다.
3. 시안 3의 값을 두 번째 테마로 추가하고, 화면 배치 규칙만 테마별로 덧씌웁니다.
4. 설정 화면의 테마 선택과 헤더 전환 버튼, 저장과 불러오기를 붙입니다.
5. 두 테마에서 검색 결과 0건(필터로 비었을 때 포함), 로딩, 오류, 분석 중, 저장됨, 필터 적용 중, 인용수 미확인 상태를 모두 확인합니다.
6. 필터 줄(5.9), 정렬 선택(5.10), 통계 상세 카드(5.11)를 두 테마에서 구현합니다.
7. 스플래시, 로그인, 가입, 승인 대기, 관리자 승인 화면(5.12~5.14)은 스플래시 이미지가 준비된 뒤 만듭니다. 그 전에는 설정 화면의 임시 로그인 입력창을 씁니다.

## 9. 시안에 없어서 구현하면서 정해야 하는 것

- 내 서재 화면, 설정 화면, 빈 상태, 오류 메시지, 로딩 표시 (시안은 검색과 상세 화면 하나뿐입니다.)
- 검색 필터 줄, 정렬 선택, 통계 상세 카드, 스플래시·로그인·가입·승인 대기·관리자 승인 화면 (시안이 없어 5.9~5.14의 규칙으로 구현합니다. 스플래시 이미지는 따로 만듭니다.)
- 전문 번역의 비용 확인 대화상자
- 작은 화면 배치
- 시안의 번역과 요약 문장은 예시입니다. 실제 값으로 바뀝니다.
