## 5.2 보안

| 점검 | 방법 | 결과 |
| --- | --- | --- |
| 키 패턴 검색 | 저장소 전체와 `dist/` 대상 grep(OpenRouter 키, `service_role`, `sb_secret_`, JWT, 개인 키, AWS 키) | 소스·빌드 결과에 비밀 값 0건(문서의 설명 문장과 테스트의 더미 값뿐). 기존 secrets 테스트도 통과 |
| OpenRouter 키 이동 | 실제 브라우저 세션의 모든 요청을 기록 | 키는 `openrouter.ai` 요청 1건의 Authorization 헤더에만 실림. URL, 본문, Supabase·글꼴 서버 요청, 화면(DOM), 쿠키, `localStorage`에는 없음. `sessionStorage`(탭)에만 있음 |
| XSS | `innerHTML` 등 검색 | 고정 아이콘 문자열에만 사용. 외부 글은 모두 `textContent`. 외부 링크는 `safeUrl` + `rel="noopener noreferrer"` |
| 콘텐츠 보안 정책(CSP) | `<meta http-equiv>`로 추가, 브라우저에서 전 과정(글꼴, 분석, PDF 처리와 워커) 확인 | 위반 0건. 허용 목록 밖 연결(`example.com`, `openrouter.ai.evil.example`)은 차단됨. 정책 내용은 테스트로 고정 |
| 중계 함수 | 소스 검토 | 로그인 + 승인 확인, 출처 검사, 요청 크기·형식 검증, 요청 내용은 로그에 남기지 않음. `service_role` 미사용 |
| RLS | `supabase/tests/rls_check.sql` 재실행(롤백되는 시험) | 22개 항목 모두 PASS. 시험 계정 잔여 0개, 데이터 행 수 불변. `anon`의 테이블 권한 없음, 정책은 모두 `authenticated` 전용 |
| Supabase 보안 점검(advisor) | `get_advisors` | 경고 3건: ① ② `rls_auto_enable()` 실행 권한(anon, authenticated), ③ 유출 비밀번호 보호 꺼짐 |

조치 결과:
- ① ②: `supabase/migrations/20261007000000_revoke_rls_auto_enable_execute.sql`을 **적용했다**(2026-10-06). 이 함수는 새 테이블에 RLS를 자동으로 켜 주는 이벤트 트리거(`ensure_rls`)용이다. 적용 뒤 advisor에서 경고 2건이 사라졌고, EXECUTE 권한은 `postgres`, `service_role`만 남았으며, 새 테이블을 만들면 RLS가 자동으로 켜지는 것을 롤백되는 시험으로 확인했다.
- ③ 유출 비밀번호 보호: **Supabase Pro 플랜 이상의 기능**이라 무료 플랜에서는 대시보드에 메뉴가 보이지 않는다(공식 문서 "Password security" 확인). 무료 플랜에서는 켤 수 없으므로 **수용하는 위험**으로 둔다. 대신 최소 비밀번호 길이 8자(Auth 설정)를 쓰고, 가입은 관리자 승인 전까지 데이터 접근이 막혀 있어 영향이 작다. Pro로 올리면 그때 켠다.

## 5.3 약관

| 점검 | 결과 |
| --- | --- |
| arXiv 호출 간격 | 브라우저 대기열 3초, 중계 함수 게이트 3초에 1번, 한 줄(연결 1개). 테스트로 고정 |
| arXiv 직접 호출 | 브라우저 코드에는 arXiv·Semantic Scholar 주소가 없음(중계 함수만 호출). 사용자를 알아볼 수 있는 User-Agent 전송 |
| PDF 비저장 | PDF 처리 코드(`src/js/pdf/*`, `pdf-screen.js`)에 저장소, 네트워크, DB 접근이 없음. 앱의 네트워크 호출은 중계 함수와 OpenRouter 두 길뿐이고 PDF를 내려받지 않음(사용자가 직접 놓은 파일만 읽음). 논문 저장 행에는 PDF 본문이 들어갈 수 없음(허용 열 목록). 모두 테스트로 고정, 위반 코드를 일부러 넣어 테스트가 잡는지 확인 |
