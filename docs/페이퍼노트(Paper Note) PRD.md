# 페이퍼노트(Paper Note) PRD

Oct 5, 2026

## 문서 개요

페이퍼노트는 영어 논문을 검색해 저장하고, AI로 요약·번역·용어 정리·앱 아이디어 도출까지 해 주는 개인용 웹앱입니다. 이메일과 비밀번호로 가입한 뒤 관리자(개발자 본인)가 승인한 사용자만 쓸 수 있습니다.

영어 논문을 읽고 정리하는 시간을 줄이는 것이 목적입니다. 통계(구조방정식모형, 다층모형)를 중심으로 데이터분석, AI·바이브 코딩, 생명과학, 학습동기, 교육심리, 교육방법 논문을 한곳에서 찾고, 필요한 만큼만 AI에 보내 비용을 아낍니다.

| 항목 | 내용 |
| --- | --- |
| 제품명 | 페이퍼노트 (Paper Note) |
| 문서 버전 | v1 초안 (2차 수정) |
| 사용자 | 개발자 본인(관리자) + 관리자가 승인한 사용자 |
| 배포 | 웹, 단일 HTML (GitHub Pages) |
| 저장소 | Supabase (데이터베이스) |
| 로그인 | Supabase Auth, 이메일과 비밀번호(8자 이상), 가입 후 관리자 승인, 확인 메일 없음 |
| AI 호출 | OpenRouter API |

## 목표와 비목표

v1은 "검색 → 저장 → 분석 → 서재"가 끊김 없이 이어지는 것을 목표로 하고, 사용자 간 공유와 자동 PDF 수집은 하지 않습니다.

**목표**

- 관심 분야 7개 프리셋으로 논문을 한 번에 검색한다.
- 기간, 최소 인용수, 검색 개수 필터와 여러 기준의 정렬로 결과를 좁히고 정리한다.
- 마음에 드는 논문의 메타데이터, AI 결과, 메모를 Supabase 서재에 저장한다.
- 초록 단계 분석은 PDF 없이 항상 가능하게 한다.
- 본문 분석은 PDF를 끌어다 놓으면 브라우저에서 텍스트를 추출해 진행한다.
- 모델 3종 중 하나를 골라 분석하고, 결과를 저장해 다시 열람한다.
- 이메일과 비밀번호로 가입·로그인하고, 관리자가 승인한 계정만 데이터를 쓸 수 있게 한다.

**비목표 (v1에서 하지 않음)**

- 사용자 간 논문·분석 결과 공유 기능 (계정은 여러 개 가능하지만 데이터는 계정별로 분리)
- 소셜 로그인, 이메일 인증, 비밀번호 재설정 메일 (v1은 이메일을 보내지 않음)
- PDF 원본의 서버 저장 (링크만 저장)
- 링크만으로 PDF를 자동 수집해 본문을 추출하는 기능
- 수업 아이디어 생성
- 유료 출판사 사이트 크롤링
- 전문 번역을 기본 흐름에 넣는 것 (선택 기능으로만 제공)

## 사용자와 사용 시나리오

주 사용자는 통계학을 전공한 개발자 본인(관리자 겸임)이며, 영어 논문을 읽고 번역하는 일이 반복되는 상황을 기준으로 설계합니다. 가입을 승인받은 다른 사용자도 쓸 수 있지만 설계 기준은 본인입니다.

1. **훑어보기**: 프리셋 "통계"를 눌러 논문 목록을 보고, 기간·인용수 필터와 정렬로 좁힌다. 초록 번역과 3줄 요약을 읽고 마음에 드는 논문만 서재에 저장한다.
2. **정독**: 저장한 논문의 PDF를 새 탭에서 열어 내 컴퓨터에 저장한다. 그 파일을 앱에 끌어다 놓으면 구조화 요약, 섹션별 번역, 용어 사전이 만들어지고, 통계 논문이면 모형·가정·추정 방법과 Python 재현 코드 뼈대도 나온다.
3. **아이디어 수집**: 논문에서 뽑힌 바이브 코딩 앱 아이디어를 서재에서 모아 보고, 마음에 드는 아이디어는 메모로 남긴다.
4. **가입과 승인**: 새 사용자가 이메일과 비밀번호로 가입하면 승인 대기 상태가 되고, 관리자가 승인하면 로그인해서 쓸 수 있다.

## 핵심 흐름

앱은 로그인 후 검색, 저장, 분석, 서재의 네 단계로 이어지고, 분석은 초록 단계와 본문 단계로 나뉩니다.

1. **검색**: 프리셋이나 검색어로 arXiv와 Semantic Scholar를 함께 검색하고, 기간·인용수·개수 필터와 정렬로 결과를 좁힌다.
2. **저장**: 마음에 드는 논문의 메타데이터와 PDF 링크를 Supabase에 저장한다.
3. **분석**: 모델을 고른 뒤 분석한다.
   - 초록 단계: 초록만으로 3줄 요약, 초록 번역, 핵심 용어 (항상 가능)
   - 본문 단계: PDF를 끌어다 놓으면 구조화 요약, 용어 사전, 섹션별 번역, 바이브 코딩 앱 아이디어 (통계 분석 모드이면 통계 상세 추가)
4. **내 서재**: 저장한 논문과 분석 결과, 메모를 다시 열람한다.

## 논문 검색

검색은 arXiv와 Semantic Scholar를 같은 형식으로 묶어 제공하고, 관심 분야 프리셋 7개로 시작하며 사용자가 프리셋을 추가할 수 있습니다.

**검색 소스**

| 소스 | 역할 | 제약 |
| --- | --- | --- |
| arXiv API | 기본 소스. 통계, AI, 생명과학 프리프린트와 PDF 주소 제공 | 요청은 3초에 1번, 연결은 1개만 허용된다 ([arXiv API 이용 약관](https://info.arxiv.org/help/api/tou.html)). 호출을 최소화하고 결과를 캐시한다. 인용수 정보는 제공하지 않는다. |
| Semantic Scholar API | 보조 소스. 분야 제한 없이 검색하고 무료 공개 PDF 주소를 제공 | 키 없이 쓰면 호출 한도가 빡빡하다고 알려져 있다. 공식 문서로 확인 필요. 교육학 분야는 이 소스가 중심이다. 인용수를 제공하며, arXiv 논문의 인용수 보강에도 쓴다. |

같은 논문이 두 소스에 모두 나오면 arXiv ID나 DOI를 기준으로 하나로 합칩니다.

**검색 프리셋 (우선순위 순)**

| 순위 | 프리셋 | 초기 검색어 (영문) | 중심 소스 |
| --- | --- | --- | --- |
| 1 | 통계 | structural equation modeling, multilevel model | arXiv(stat.ME, stat.AP) + Semantic Scholar |
| 2 | 데이터분석 | data analysis, statistical computing, Python | arXiv + Semantic Scholar |
| 3 | AI·바이브 코딩 | large language model, vibe coding, AI-assisted programming | arXiv(cs.AI, cs.LG, cs.SE) |
| 4 | 생명과학 | computational biology, bioinformatics | arXiv(q-bio) + Semantic Scholar |
| 5 | 학습동기 | learning motivation, self-determination theory | Semantic Scholar |
| 6 | 교육심리 | educational psychology | Semantic Scholar |
| 7 | 교육방법 | instructional method, active learning | Semantic Scholar |

기본 프리셋 7개는 **가입이 승인되는 순간 DB가 계정마다 만들어 줍니다.** (프리셋이 하나도 없는 계정에만 채우므로 다시 승인되어도 중복되지 않고, 사용자가 지운 프리셋을 되살리지 않습니다.) 소스는 1~4번이 arXiv와 Semantic Scholar 둘 다, 5~7번이 Semantic Scholar만입니다. arXiv 분류는 표의 분류를 쓰고 생명과학은 `q-bio.*`입니다. 기본 정렬은 새 논문이 중요한 1~4번이 최신순, 교육 분야인 5~7번이 관련도순이며, 통계 분석 모드는 "통계"와 "데이터분석"에서 켜집니다. 기간과 인용수 필터는 "제한 없음", 검색 개수는 20입니다.

초기 검색어는 제안이며 앱에서 바꿀 수 있습니다. 프리셋 하나는 이름, 순서, 영문 검색어, 소스(arXiv, Semantic Scholar, 둘 다), arXiv 분류(선택), 기본 정렬, 검색 필터(기간, 최소 인용수, 검색 개수), 통계 분석 모드 여부로 이루어지고 Supabase에 저장됩니다. 사용자는 프리셋을 추가, 수정, 삭제하고 순서를 바꿀 수 있습니다.

**검색 필터**

필터는 검색창 옆에서 고르고, 값은 프리셋에 저장됩니다. 검색창에서 바꾼 값은 그 검색에만 적용되고, 프리셋을 수정해야 저장됩니다.

| 필터 | 선택지 | 기본값 | 적용 방식 |
| --- | --- | --- | --- |
| 기간 | 6개월, 1년, 3년, 5년, 10년, 제한 없음 | 제한 없음 | arXiv는 제출일 범위로 요청한다. Semantic Scholar는 연 단위로 요청한 뒤, 가져온 결과를 발행일 기준으로 브라우저에서 다시 거른다 |
| 최소 인용수 | 제한 없음, 10, 50, 100, 500 이상 + "인용수 미확인 포함" 체크 | 제한 없음 | Semantic Scholar 조건으로 요청하고, 합친 결과를 브라우저에서 다시 거른다 |
| 검색 개수 | 10, 20, 30, 50, 100 | 20 | 두 소스를 합치고 중복을 제거한 뒤의 최종 개수 |

- 검색 개수는 소스별이 아니라 합친 뒤의 총 개수입니다. 필터로 줄어도 개수를 채우려고 소스별로 더 요청할 수 있고, 소스별 한 번 요청 상한(Semantic Scholar 100건)을 넘기지 않습니다. 조건에 맞는 논문이 모자라면 있는 만큼만 보여 주고 "조건에 맞는 논문이 N건입니다"라고 알립니다.
- arXiv는 인용수를 주지 않으므로, 합친 결과의 인용수는 Semantic Scholar 일괄 조회로 보강합니다. 조회에 실패했거나 없는 논문은 "인용수 미확인"으로 두며, 최소 인용수 필터에서는 "인용수 미확인 포함"을 체크해야 보입니다.
- 최신 논문은 인용수가 적어서 짧은 기간과 높은 최소 인용수를 함께 걸면 결과가 비기 쉽습니다. 결과가 0건이면 조건을 완화하라는 안내와 필터 해제 버튼을 보여 줍니다.
- 필터를 바꾸면 "검색" 버튼을 눌렀을 때 적용합니다. 값마다 자동으로 다시 검색하지 않아 호출을 아낍니다.
- 검색어는 쉼표로 구분한 영문 단어이고 최대 3개입니다. 한글과 특수문자는 무시하며, 영문이 하나도 없으면 검색하지 않습니다. 여러 개이면 arXiv에는 OR 검색식 하나로, Semantic Scholar에는 검색어마다 한 번씩 요청해 합칩니다.
- 한 소스가 호출 한도나 서버 오류로 실패해도 다른 소스의 결과는 보여 주고, 실패한 소스는 경고로 알립니다. 일부가 실패한 결과는 캐시하지 않습니다. 로그인·승인·네트워크 오류는 검색 전체를 멈춥니다.
- 필터로 줄어든 개수를 채우려고 다음 쪽을 더 가져오는 것은 최대 3번(첫 쪽 포함)까지입니다. 그래도 모자라면 있는 만큼만 보여 줍니다.

**검색 결과 정렬**

정렬은 이미 가져온 결과를 브라우저에서 다시 늘어놓는 것이라 추가 호출 없이 바로 바뀌고, 기본값은 프리셋의 기본 정렬입니다.

| 기준 | 설명 |
| --- | --- |
| 관련도 (기본) | 소스가 준 순서를 유지 |
| 최신순 / 오래된순 | 발행일 기준 |
| 인용수 많은순 | 인용수 미확인 논문은 맨 뒤 |
| 연평균 인용수순 | 인용수 ÷ 발행 후 경과 연수(최소 1년). 최신 논문이 오래된 논문에 밀리지 않게 보정 |
| 저자 이름순 | 첫 저자의 성 기준 A→Z |
| 제목순 | A→Z |
| PDF 있는 논문 우선 | 본문 단계 분석이 가능한 논문을 위로 |

- 값이 같으면 관련도 순서를 따릅니다.
- 내 서재도 같은 정렬 컴포넌트를 쓰고, "저장일순"과 직접 정하는 "내 순서"(기본)를 추가로 제공합니다. "맨 위에 고정"한 논문은 어떤 정렬에서도 목록 맨 위에 옵니다.

## AI 분석

분석은 OpenRouter로 세 모델 중 하나를 골라 실행하며, 기본값은 Claude Sonnet 5.5이고 GPT-6 Luna와 Gemini 3.8 Flash는 보조용입니다.

| 역할 | 모델 ID | 가격 (입력/출력, 100만 토큰당) | 추론 설정 |
| --- | --- | --- | --- |
| 기본 | `anthropic/claude-sonnet-5.5` | $2 / $10 | 항상 켜짐, 강도로 조절 |
| 보조 | `google/gemini-3.8-flash` | $0.75 / $3.75 | 항상 켜짐, 강도(low, medium, high)로 조절 |
| 보조 | `openai/gpt-6-luna` | $0.10 / $0.50 | 끌 수 있음 (none부터 max까지) |

모델 ID는 위 표의 이름 그대로 고정하고, `latest` 별칭은 쓰지 않습니다. 별칭은 모델이 바뀌면 같은 논문의 결과가 달라지기 때문입니다. 번역과 요약은 추론 강도를 낮게(low, Luna는 none) 시작하고 품질을 보며 올립니다.

**분석 단계와 결과물**

| 단계 | AI에 보내는 입력 | 결과물 |
| --- | --- | --- |
| 초록 단계 | 초록 | 3줄 요약, 초록 번역, 핵심 용어 |
| 본문 단계 | 추출한 본문 텍스트 (참고문헌 제외) | 구조화 요약(연구 목적, 방법, 결과, 한계), 용어 사전, 섹션별 번역, 바이브 코딩 앱 아이디어, 통계 상세(통계 분석 모드일 때) |
| 전문 번역 (선택) | 추출한 본문 전체 또는 섹션 하나 | 전체 번역(섹션 하나만 요청 가능), 실행 전 비용 확인창 필수 |

**출력 형식**

결과는 JSON으로만 받아 화면에서 카드로 그립니다. 항목 이름은 아래와 같습니다.

```json
{
  "summary_3lines": ["", "", ""],
  "structured_summary": { "purpose": "", "method": "", "results": "", "limitations": "" },
  "abstract_translation": "",
  "glossary": [{ "term": "", "ko": "", "explanation": "" }],
  "section_translations": [{ "title": "", "ko": "" }],
  "app_ideas": [{
    "name": "",
    "one_liner": "",
    "evidence": "",
    "core_features": ["", "", ""],
    "difficulty": "easy | medium | hard",
    "single_html_possible": true,
    "first_prompt": ""
  }],
  "statistics_details": {
    "is_statistical": true,
    "model": "",
    "assumptions": ["", ""],
    "estimation_method": "",
    "software": [""],
    "sample": "",
    "fit_indices": [{ "name": "", "value": "" }],
    "python_skeleton": ""
  }
}
```

**통계 분석 모드**

통계 논문은 `statistics_details`를 추가로 받습니다. 본문 단계에서만 채우며, 논문 상세 화면의 "통계 분석 모드" 토글로 켜고 끕니다. 프리셋 "통계"와 "데이터분석"은 기본으로 켜져 있습니다. 꺼져 있으면 `statistics_details`는 `null`이고, 켜져 있어도 통계 논문이 아니면 `is_statistical`을 false로 두고 나머지는 비웁니다. 출력이 약 1천 토큰 늘어납니다.

**프롬프트 원칙**

- 논문에 없는 내용은 지어내지 않고 "언급 없음"으로 적는다.
- 용어는 한국어 번역과 영어 원어를 함께 적는다.
- 설명과 번역은 한국어로, JSON 외의 문장은 출력하지 않는다.
- 앱 아이디어에는 근거가 된 논문 내용과 Claude Code나 Antigravity에 바로 넣을 첫 프롬프트 초안을 포함한다.
- 통계 상세 항목(모형, 가정, 추정 방법, 소프트웨어, 표본, 적합도 지수)은 논문에 나온 내용만 적고, 없으면 "본문에 언급 없음"으로 적는다.
- `python_skeleton`은 논문의 코드가 아니라, 논문에 나온 모형과 추정 방법을 바탕으로 AI가 만든 재현 코드 초안이다. 화면에 "AI 생성 초안"으로 표시하고, 논문에 없는 설정은 주석에 TODO로 남긴다.

## PDF 처리

초록 단계는 PDF 없이 항상 동작하고, 본문 단계는 사용자가 PDF를 앱에 끌어다 놓을 때만 동작합니다. 앱은 PDF 원본을 저장하거나 서버에서 내려받지 않습니다.

**본문 단계 흐름**

1. 논문 카드의 "원문 PDF 열기"를 누르면 새 탭에서 PDF가 열리고, 사용자가 직접 내 컴퓨터에 저장한다.
2. 저장한 PDF를 논문 상세 화면의 끌어다 놓기 영역에 놓는다. 해당 논문에 파일이 연결된다.
3. pdf.js가 브라우저 안에서 텍스트를 추출한다. 추출 결과는 미리보기로 보여 준다.
4. 제목(Abstract, Introduction, Method, Results, Discussion 등)을 기준으로 섹션을 나눈다. 제목을 찾지 못하면 페이지 단위로 나눈다.
5. 참고문헌 섹션을 뺀 텍스트만 AI에 보내 토큰을 아낀다.
6. 분석 결과를 Supabase에 저장한다. PDF 파일과 추출 텍스트는 저장하지 않는다.

**알려진 한계와 대응**

| 한계 | 대응 |
| --- | --- |
| 2단 편집 논문, 수식은 추출 텍스트가 뒤섞일 수 있음 | 추출 미리보기를 보여 주고, 섹션 분할이 어긋나면 페이지 단위로 전환 |
| 스캔본 PDF는 텍스트가 추출되지 않음 | 텍스트가 없으면 경고하고 초록 단계 분석만 안내 |
| 유료 저널 논문은 PDF를 받을 수 없음 | 메타데이터, 초록, DOI 링크만 저장하고 초록 단계로 분석 |

## 데이터 모델

Supabase에는 프로필, 논문, 분석 결과, 프리셋 네 테이블을 두고, 메모는 논문 테이블의 열로 시작합니다. 테이블 이름에는 `pn_` 접두사를 붙입니다. (Paper Note 전용 프로젝트이지만, 다른 프로젝트와 합칠 때 이름이 겹치지 않게 하려는 것입니다.) 논문, 분석, 프리셋은 `user_id`(로그인한 계정)로 소유자를 구분합니다.

| 테이블 | 주요 열 | 비고 |
| --- | --- | --- |
| `pn_papers` | id, user\_id, source(arxiv 또는 semantic\_scholar), source\_id, title, authors, year, published\_date, citation\_count, abstract, doi, pdf\_url, landing\_url, categories, memo, saved\_at, preset\_id, pinned, sort\_index | 저장한 논문 한 건이 한 행. 같은 사용자의 같은 source와 source\_id는 중복 저장 불가. citation\_count는 저장 시점의 값. preset\_id는 그 논문이 나온 검색의 프리셋(서재의 프리셋별 필터용)이며, 프리셋을 지우면 null이 되고 남의 프리셋은 가리킬 수 없다. pinned는 서재의 "맨 위에 고정", sort\_index는 "내 순서" 정렬의 자리 번호(작을수록 앞, null이면 아직 순서를 정하지 않은 새 논문이라 맨 앞) |
| `pn_analyses` | id, user\_id, paper\_id, stage(abstract 또는 fulltext), model, result\_json, created\_at | 같은 논문을 모델별, 단계별로 여러 번 저장 가능 |
| `pn_presets` | id, user\_id, name, position, query, sources, arxiv\_categories, sort, date\_range, min\_citations, result\_limit, stats\_mode | 기본 7개 + 사용자 추가분. sort는 기본 정렬 |
| `pn_profiles` | id(= 로그인 계정 id), email, status(pending, approved, rejected), is\_admin, created\_at, approved\_at | 가입할 때 자동으로 만들어지고(status=pending), 승인 여부와 관리자 여부를 담음 |

- `result_json`에는 AI 분석 섹션의 JSON 출력을 그대로 저장한다.
- PDF 원본과 추출 텍스트는 저장하지 않고 `pdf_url`과 `landing_url`만 둔다.
- 모든 테이블은 RLS를 켠다. 정책은 아래 "로그인과 가입 승인"을 따른다.

## 로그인과 가입 승인

로그인은 Supabase Auth의 이메일과 비밀번호 방식이고, 가입한 계정은 관리자가 승인해야 데이터를 쓸 수 있습니다.

- **방식**: 이메일과 비밀번호(8자 이상). Supabase의 "Confirm email"은 꺼서 인증 메일을 보내지 않습니다. 소셜 로그인은 없습니다.
- **가입**: 가입하면 `pn_profiles`에 `status = pending`인 행이 자동으로 생깁니다. 인증 메일이 없으므로 가입 직후 로그인 세션이 만들어지지만, 승인 전에는 RLS가 모든 데이터 접근을 막고 앱은 승인 대기 화면만 보여 줍니다.
- **승인**: 관리자만 `status`를 바꿀 수 있습니다. 앱 안의 승인 화면(F20)이 나오기 전에는 Supabase 대시보드에서 직접 바꿉니다. 첫 관리자는 개발자 본인 계정을 SQL로 `is_admin = true`, `status = approved`로 지정합니다.

| 상태 | 로그인 | 데이터 접근 | 화면 |
| --- | --- | --- | --- |
| pending | 가능 | 불가 | 승인 대기 안내 |
| approved | 가능 | 본인 데이터만 | 정상 사용 |
| rejected | 가능 | 불가 | "승인되지 않았습니다" 안내 |

**정책 규칙**

- 논문, 분석, 프리셋: `user_id = auth.uid()`이고 `status = approved`인 계정만 읽고 쓴다.
- `pn_profiles`: 일반 사용자는 자기 행을 읽기만 한다. `status`와 `is_admin`은 관리자만 바꿀 수 있고, 사용자가 자기 행을 고쳐 스스로 승인하거나 관리자가 되는 일이 없어야 한다.
- 승인 여부와 관리자 여부를 확인하는 DB 함수는 `security definer`로 만들어 정책끼리 서로를 참조하다 막히는 일을 피한다.
- 앱 코드에는 Supabase 공개용(anon 또는 publishable) 키만 넣는다. `service_role` 키는 코드, 저장소, 브라우저 어디에도 넣지 않는다.
- 비밀번호는 Supabase Auth가 해시로 관리하며 앱은 저장하지 않는다.

## 화면 구성

화면은 검색, 서재, 논문 상세, 설정 네 개이고, 로그인 전에는 스플래시·로그인(가입 포함)과 승인 대기 화면이 앞에 놓입니다. 분석은 논문 상세 화면에서 실행합니다.

| 화면 | 구성 요소 |
| --- | --- |
| 검색 | 프리셋 탭(7개 + 추가), 검색창, 소스 선택, 검색 필터(기간, 최소 인용수, 개수), 정렬 선택, 결과 카드(제목, 저자, 연도, 인용수, 초록 미리보기, 저장, 원문 PDF 열기, 초록 분석) |
| 서재 | 저장한 논문 목록, 프리셋별 필터, 분석 여부 표시, 정렬(내 순서 + 저장일순 + 검색 정렬 기준), 카드의 맨 위 고정·끌어서 순서 바꾸기·삭제 |
| 논문 상세 | 메타데이터, 모델 선택, 통계 분석 모드 토글, 분석 실행과 예상 비용, 결과 탭(요약, 번역, 용어, 통계 상세, 앱 아이디어), PDF 끌어다 놓기 영역, 메모 |
| 설정 | OpenRouter API 키 입력, 기본 모델, 프리셋 관리, 계정(이메일, 로그아웃), 가입 승인 목록(관리자만), Supabase 연결 상태 |
| 스플래시 · 로그인 | 스플래시 이미지와 앱 제목, 이메일·비밀번호 입력, 로그인, 회원가입 전환 |
| 승인 대기 | 승인되지 않은 계정에게 보이는 안내, 상태 새로고침, 로그아웃 |

검색 결과 카드에서는 원문 PDF 링크와 함께 논문의 초록 페이지 링크도 보여 줍니다. 이미 서재에 저장한 논문은 카드에 "저장됨"으로 표시합니다. 카드에는 인용수도 보여 주고, 확인하지 못한 논문은 "인용수 미확인"으로 표시합니다.

**화면 테마**

사용자는 두 가지 디자인 중 하나를 골라 쓸 수 있습니다. 테마 이름과 구현 규칙은 DESIGN.md를 따릅니다.

- 학술: 인디고와 와인 색, 명조 계열 제목, 3열 화면 (시안 1)
- 교육용: 따뜻한 리넨 배경, 상단 4단계 표시, 2열 화면 (시안 3)
- 두 테마는 같은 HTML 구조를 쓰고 CSS 변수와 화면 배치 규칙만 바꿉니다.
- 선택한 테마는 브라우저에 기억하고, 처음 열 때는 마지막 선택을 바로 적용해 화면이 깜빡이지 않게 합니다.
- 새 화면(서재, 설정 등)을 만들 때마다 두 테마에서 모두 확인합니다.
- 로그인 전 화면에도 마지막으로 고른 테마가 적용됩니다. 저장값이 없으면 학술 테마입니다.

## 비기능 요구사항

API 키는 사용자가 필요할 때만 입력하고 탭을 닫으면 사라져야 하며, 논문 PDF는 서버에 저장하지 않아야 합니다.

**API 키 보안**

- 키 입력창에 입력하고, 값은 탭을 닫으면 지워지는 `sessionStorage`에만 둔다. `localStorage`와 Supabase, 코드에는 넣지 않는다.
- 키는 `openrouter.ai`로 가는 요청에만 사용한다.
- OpenRouter에서 이 키에 소액 사용 한도를 설정할 수 있으면 설정한다.
- 분석할 때 논문 텍스트는 OpenRouter를 거쳐 선택한 모델 제공사로 전송된다.
- 사용자마다 자기 OpenRouter 키를 입력하며, 분석 비용은 각자의 키에서 청구된다.

**비용**

논문 한 편(본문 약 3만 토큰)을 분석할 때의 대략적인 비용입니다. 구조화 요약은 출력 약 2천 토큰, 전문 번역은 출력 약 3만 토큰으로 계산했고, 추론 토큰은 포함하지 않았습니다.

| 작업 | GPT-6 Luna | Gemini 3.8 Flash | Claude Sonnet 5.5 |
| --- | --- | --- | --- |
| 구조화 요약 | 약 0.4센트 | 약 3센트 | 약 8센트 |
| 전문 번역 | 약 2센트 | 약 14센트 | 약 36센트 |

통계 분석 모드는 출력이 약 1천 토큰 늘어나 Claude Sonnet 5.5는 약 1센트, Gemini 3.8 Flash는 약 0.4센트, GPT-6 Luna는 약 0.05센트가 더 듭니다.

전문 번역과 입력이 큰 분석은 실행 전에 예상 토큰과 비용을 보여 주고 확인을 받습니다.

전문 번역은 섹션 하나만 요청할 수도 있고, 이때는 그 섹션 분량의 비용만 듭니다. 앱은 한국어 번역의 토큰이 영어 원문보다 많다는 점을 반영해 출력을 입력의 약 1.5배로 어림하므로, 위 표(1:1 가정)보다 예상 비용이 조금 더 크게 나옵니다. 번역 결과는 섹션 단위로 `pn_analyses`(단계 `translation`)에 저장됩니다.

**성능**

- 두 검색 소스는 동시에 호출하되, arXiv 요청은 3초 간격 대기열로 보낸다.
- 같은 검색어와 필터의 결과는 캐시해 프리셋을 오가도 다시 호출하지 않는다.
- arXiv 결과의 인용수 보강은 중복을 합친 뒤 Semantic Scholar 일괄 조회 한 번으로 처리하고, 검색 결과와 함께 캐시한다. 정렬은 추가 호출을 하지 않는다.

**저작권과 이용 약관**

- arXiv는 메타데이터의 저장과 공유를 허용하고, 논문 내용은 개인용이나 연구용으로 저장해 쓰는 것을 허용한다. 반면 PDF 같은 e-print를 내 서버에서 저장해 제공하는 것은 허락 없이 할 수 없다 ([arXiv API 이용 약관](https://info.arxiv.org/help/api/tou.html)). 그래서 앱은 PDF 링크만 저장한다.
- 유료 출판사 사이트는 크롤링하지 않는다.

## 기술 스택과 구조

앱은 별도 서버 없이 브라우저의 단일 HTML 파일이 모든 호출을 맡는 구조입니다.

- 화면과 로직: Vanilla JS, 단일 HTML 파일
- 배포: GitHub Pages
- 저장과 로그인: Supabase (Paper Note 프로젝트의 데이터베이스와 Supabase Auth 이메일·비밀번호 로그인)
- AI: OpenRouter API (사용자가 입력한 키)
- PDF 텍스트 추출: pdf.js (브라우저 안에서 실행)
- 검색 소스는 어댑터로 분리해 제목, 저자, 연도, 초록, DOI, PDF 주소의 같은 형식으로 변환한다. 소스를 추가해도 화면은 바뀌지 않는다.

&#91;embedded content: 앱 구조 · 브라우저 1곳, 외부 서비스 4곳\]

화면은 두 검색 소스, OpenRouter, Supabase를 직접 호출합니다. 브라우저에서의 직접 호출이 CORS로 막히면 그 호출만 Supabase Edge Function으로 중계합니다.

## 개발 단계

v1은 네 마일스톤으로 나누고, 다음 마일스톤은 앞 단계의 완료 기준을 통과한 뒤에 시작합니다.

&#91;embedded content: 개발 로드맵 · 마일스톤 4개, 완료 기준 3개\]

M1은 CORS 호출 테스트로 시작합니다. 테스트 대상에는 Semantic Scholar 인용수 일괄 조회와 날짜 범위 요청도 넣습니다. 막히는 호출이 있으면 Supabase Edge Function 중계를 M1 범위에 넣습니다. M1에는 Supabase 로그인(임시 이메일·비밀번호 입력창)과 `pn_profiles`, 승인 상태를 반영한 RLS 정책도 넣습니다.

우선순위 P0 기능은 M1부터 M3까지에, P1과 P2 기능은 M3와 M4에 나눠 담았습니다. 검색 필터와 정렬(F21, F22)은 M2에, 통계 분석 모드(F23)는 M3에 넣습니다. 스플래시와 정식 로그인·가입·승인 대기 화면(F18, F19)과 관리자 승인 화면(F20)은 두 번째 테마와 함께 M4에서 완성합니다. 화면 테마는 M1에서 색, 글꼴, 모서리를 CSS 변수로 분리해 두고, M4에서 두 번째 테마와 선택 화면을 완성합니다.

## 리스크와 열린 질문

가장 큰 미확인 가정은 브라우저에서 두 검색 API를 직접 호출할 수 있는지(CORS)와, 가입 승인 방식의 로그인에서 계정별 데이터를 지키는 Supabase 접근 제어(RLS)입니다.

| 리스크 | 내용 | 대응 |
| --- | --- | --- |
| CORS | arXiv와 Semantic Scholar를 브라우저에서 직접 호출할 수 있는지 확인하지 못함 (인용수 일괄 조회, 날짜 범위 요청 포함) | 첫 마일스톤에서 가장 먼저 테스트하고, 막히면 Supabase Edge Function으로 중계 |
| Supabase 접근 제어 | anon 키는 공개되므로 정책이 허술하면 누구나 읽고 쓸 수 있음. 확인 메일이 없어 가입 직후에도 세션이 생김 | 결정: 이메일·비밀번호 로그인, 계정별 RLS, 관리자가 승인한 계정만 데이터 접근. 사용자가 자기 승인 상태를 바꾸지 못하는지 M1에서 직접 시험 |
| PDF 추출 품질 | 2단 편집, 수식, 스캔본에서 텍스트가 깨질 수 있음 | 추출 미리보기, 페이지 단위 분할, 텍스트 없음 경고 |
| 교육학 논문 소스 | arXiv에는 교육학 논문이 거의 없음 | Semantic Scholar 중심으로 시작하고, 필요하면 ERIC 어댑터 추가 (아직 확인하지 못함) |
| 번역 품질 차이 | 모델마다 통계 논문의 번역 품질이 다를 수 있음 | 같은 논문을 세 모델로 비교한 뒤 기본 모델을 확정 |
| Semantic Scholar 호출 한도 | 키 없이 쓰면 한도에 걸릴 수 있음. 검색 개수 100개와 인용수 일괄 조회가 호출을 늘림 | 결과 캐시, 필요하면 키를 사용자가 입력하는 방식으로 추가 |
| 이메일 미확인 가입 | 확인 메일을 보내지 않아 남의 이메일로도 가입을 신청할 수 있음 | 승인 전에는 데이터 접근이 막혀 영향이 작음. 승인할 때 이메일 주소를 확인하고, 가입 남용이 보이면 CAPTCHA나 가입 제한을 추가 |
| 비밀번호 분실 | 재설정 메일을 보내지 않아 사용자가 직접 재설정할 수 없음 | 관리자가 Supabase 대시보드에서 재설정. 사용자가 늘면 재설정 메일 도입을 검토 |
| 인용수 정확도 | arXiv 논문의 인용수는 Semantic Scholar 값으로 보강하므로 일부는 미확인이거나 다른 서비스와 값이 다를 수 있음 | "인용수 미확인" 표시와 필터의 "미확인 포함" 옵션. 일괄 조회 한도는 M1에서 확인 |

**열린 질문**

- [x] Supabase 로그인 방식: 이메일과 비밀번호, 가입 후 관리자 승인, 확인 메일 없음 (확정)
- [x] 통계 논문용 추가 항목(모형, 가정, 추정 방법, 소프트웨어, 표본, 적합도 지수, Python 재현 코드 뼈대): 포함, 통계 분석 모드 토글로 켜고 끔 (확정)
- [ ] 성공 기준(분석 1건당 허용 비용, 검색부터 저장까지 걸리는 시간)을 정한다.
- [x] 스플래시와 로그인은 **한 화면**으로 한다. (2026-10-06 결정) 이미 로그인된 승인 계정은 로고만 잠깐(약 1초) 보이고 바로 넘어간다.
