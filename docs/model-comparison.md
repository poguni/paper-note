# 모델 비교와 기본 모델 확정 (Implementation_Plan 3.16)

**목적**: 같은 통계 논문 1편을 모델 3종으로 분석해 번역·요약 품질과 비용을 비교하고, 기본 모델(현재 **Claude Sonnet 5.5**)을 유지할지 정한다.

이 문서는 비교 결과를 적는 틀이다. 아래 "1. 준비"와 "2. 실행"을 따라 하고, "3~6"의 빈칸을 채운다. 결정은 "7"에 적는다.

| 모델 | ID | 가격 (입력/출력, 100만 토큰당) | 기본 추론 설정 |
| --- | --- | --- | --- |
| Claude Sonnet 5.5 (현재 기본) | `anthropic/claude-sonnet-5.5` | $2 / $10 | low |
| Gemini 3.8 Flash | `google/gemini-3.8-flash` | $0.75 / $3.75 | low |
| GPT-6 Luna | `openai/gpt-6-luna` | $0.10 / $0.50 | none |

## 1. 준비

### 비교할 논문 고르기
- **통계 논문 1편**(필수): 모형, 추정 방법, 소프트웨어, 적합도 지수가 본문에 나오는 논문. 예: lme4 논문(arXiv 1406.5823), 구조방정식모형이나 다층모형을 쓴 연구 논문.
- 가능하면 **PDF가 있는 논문**으로 본문 단계까지 비교한다(품질 차이는 본문 단계에서 더 크게 난다).
- 선택: **비통계 논문 1편**(예: 교육 분야). 통계 모드가 "통계 논문이 아님"을 제대로 가려내는지 보려면 필요하다.

### 비교 방법 두 가지 (둘 중 하나, 또는 둘 다)
| | 방법 A. 앱에서 직접 | 방법 B. 자동 비교 스크립트 |
| --- | --- | --- |
| 하는 일 | 앱에서 모델을 바꿔 가며 같은 논문을 분석하고 "저장된 결과" 선택 목록으로 비교 | 한 번의 실행으로 3모델 결과와 비용, 객관 지표를 표와 보고서 파일로 모음 |
| 장점 | 실제 사용 화면 그대로 평가, 결과가 서재에 저장됨 | 같은 입력, 같은 조건, 지표가 자동 계산됨, 나란히 읽기 쉬움 |
| 단점 | 모델마다 눌러야 하고 비용·시간을 직접 기록 | 키를 환경 변수로 넣어야 함 |
| 비용 | 한 편당 모델별로 아래 "예상 비용" | 3모델 합계(실행 전에 예상 합계를 보여 줌) |

**예상 비용(본문 3만 토큰 기준, PRD 비용 표)**: 구조화 요약 Luna 약 0.4센트 / Gemini 약 3센트 / Claude 약 8센트(통계 모드는 약 1센트 안팎 추가). 초록 단계는 모델마다 약 1센트 이하다.

## 2. 실행

### 방법 A. 앱에서 직접
1. `npm run build`, `npm run serve`로 앱을 열고 로그인, API 키 입력.
2. 논문을 검색해 선택하고, 본문 단계를 보려면 PDF를 끌어다 놓는다.
3. 모델을 **Claude → Gemini → Luna** 순서로 바꿔 가며 같은 단계(초록 또는 본문)에서 "분석" (통계 모드는 세 번 모두 같은 설정으로).
4. 결과 하단의 **실제 비용**과 분석 시간(체감)을 아래 표에 적는다.
5. 논문 상세의 "저장된 결과" 선택 목록으로 모델별 결과를 오가며 읽는다. (논문을 저장해 두면 나중에 서재에서도 다시 볼 수 있다.)

### 방법 B. 자동 비교 스크립트 (`tests/manual/model-compare.mjs`)
**키는 대화창이 아닌 별도의 PowerShell 창에서 입력한다.**

초록 단계 (PDF 불필요, arXiv ID만 있으면 됨):
```powershell
cd C:\WORK-Claude\PaperNote
$k = Read-Host "OpenRouter 키" -AsSecureString
$env:OPENROUTER_API_KEY = [System.Net.NetworkCredential]::new("", $k).Password
node tests/manual/model-compare.mjs --stage abstract --arxiv 1406.5823
Remove-Item Env:OPENROUTER_API_KEY
```

본문 단계 (앱의 PDF 드롭존에서 **"추출 본문 내려받기"**로 받은 텍스트 파일을 쓴다):
```powershell
node tests/manual/model-compare.mjs --stage fulltext --text "C:\경로\논문-추출본문.txt" --title "논문 제목" --year 2014 --stats
```

옵션: `--stats`(통계 분석 모드), `--models a,b`(일부 모델만), `--effort low`(모든 모델 추론 강도를 같게), `--yes`(예상 합계가 0.5달러 이상이어도 실행). 결과는 `tests/manual/out/`에 보고서(`.md`)와 원본(`.json`)으로 저장된다.

> 한국어가 깨져 보이면 PowerShell에서 `Get-Content 파일.md -Encoding UTF8`로 읽거나 편집기로 연다.

스크립트가 모아 주는 객관 지표:
- **시도 횟수**: 1이 아니면 첫 응답이 형식 검증을 통과하지 못해 다시 요청한 것(형식 안정성)
- **근거 없는 숫자**: 결과의 수치(소수점이 있거나 두 자리 이상)가 입력 글에 없는 개수. 지어냈을 가능성의 신호이며, 0이 아니면 보고서에서 해당 수치를 확인한다.
- **섹션 범위**: 입력의 `## 제목` 섹션 중 섹션별 번역에 나온 비율(본문 단계)
- **한국어 비율**, **"언급 없음" 개수**, 용어 수, 앱 아이디어 수

## 부록: 비교를 믿을 수 있게 하는 조건
- 세 모델에 **같은 프롬프트, 같은 입력, 같은 스키마**를 쓴다(앱과 스크립트 모두 같은 코드).
- 한 번의 실행은 표본이 1개라 우연이 섞일 수 있다. 결정이 애매하면 **다른 논문으로 한 번 더** 비교한다.
- 추론 강도가 다르면 비용과 품질이 함께 달라진다. 공정하게 보려면 `--effort low`로 맞춘 결과도 한 번 본다(Luna는 기본이 `none`이라 따로 `low` 결과를 보는 것이 좋다).
- 비용은 OpenRouter가 응답에 담아 주는 **실제 청구 금액**을 쓴다(토큰 어림값이 아니다).
