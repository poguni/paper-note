# 페이퍼노트(Paper Note) 개발 보고서 (v1)

- 작성일: 2026-10-06
- 버전: v1 (첫 보고서)
- 배포 주소: https://poguni.github.io/paper-note/
- 저장소: https://github.com/poguni/paper-note (public)

## 1. 개요

**페이퍼노트**는 영어 논문을 검색하고, 저장하고, 인공지능으로 분석·요약·번역하는 개인용 웹 앱입니다. 통계학과 교육학 논문을 읽는 연구자를 대상으로 합니다.

| 항목 | 내용 |
| --- | --- |
| 한 줄 소개 | arXiv와 Semantic Scholar를 한 번에 검색하고, 마음에 드는 논문을 서재에 저장해 AI로 읽기 쉽게 정리하는 앱 |
| 대상 사용자 | 통계·교육 분야 논문을 읽는 연구자(개발자 본인과, 관리자가 승인한 소수의 사용자) |
| 개발 기간 | 2026-10-05 ~ 2026-10-06 (문서와 커밋 기록 기준) |
| 개발 방식 | 사용자(기획, 결정, git 작업)와 Claude Code(설계, 구현, 시험, 문서)의 대화형 협업. Phase 단위로 진행 |
| 규모 | 앱 소스(`src/js`) 약 5,500줄, 자동 테스트 34개 파일 398건, DB 마이그레이션 5건 |

## 2. 목표 및 배경

- 영어 논문을 읽는 데 드는 시간을 줄입니다. 논문을 찾는 단계부터 저장, 요약, 번역, 용어 정리까지 한 앱에서 이어지게 합니다.
- v1의 목표는 **"검색 → 저장 → 분석 → 서재"가 끊김 없이 이어지는 것**입니다. 사용자 간 공유와 자동 PDF 수집은 하지 않습니다.
- 핵심 가치는 세 가지입니다. ① 논문을 빠르게 거른다(프리셋, 필터, 정렬). ② 읽기 전에 핵심과 비용을 안다(3줄 요약, 구조화 요약, 예상 비용). ③ 연구 자료를 안전하게 다룬다(API 키와 PDF 원본을 서버에 저장하지 않음).
- 통계 논문에는 모형, 가정, 추정 방법, 적합도 지수를 정리하고 재현용 Python 코드 뼈대를 만들어 주는 "통계 분석 모드"를 둡니다.

## 3. 주요 기능

**검색**
- arXiv와 Semantic Scholar를 한 번에 검색하고, 같은 논문은 합칩니다. 영문 검색어 최대 3개(쉼표 구분).
- 기간, 최소 인용수, 검색 개수 필터와 8가지 정렬. 인용수를 확인하지 못한 논문은 "인용수 미확인"으로 표시하고 필터에서 포함 여부를 고릅니다.
- 검색 프리셋: 기본 7개(승인할 때 DB가 만듦)에 사용자가 추가, 수정, 삭제, 순서 변경. 프리셋마다 정렬, 필터, 통계 분석 모드까지 저장합니다.
- 같은 검색은 캐시해서 다시 호출하지 않습니다.

**서재**
- 논문 저장, 메모, 프리셋별·분석 여부별 거르기, 정렬(내 순서 + 저장일순 + 검색 기준 7개).
- 카드를 끌어서 읽을 순서를 정하고(키보드로도 가능), 별표로 맨 위에 고정하고, 휴지통으로 삭제합니다.

**AI 분석 (OpenRouter, 브라우저에서 직접 호출)**
- **초록 단계**: 3줄 요약, 초록 번역, 핵심 용어 사전.
- **본문 단계**(사용자가 PDF를 끌어다 놓음): 구조화 요약(연구 목적, 방법, 결과, 한계), 섹션별 요약 번역, 용어 사전, 통계 상세와 Python 코드 뼈대(AI 생성 초안 표시 고정), 바이브 코딩 앱 아이디어(첫 프롬프트 초안 포함).
- 섹션 하나 또는 본문 전체의 **전문 번역**(예상 비용 확인창, 진행 상태, 취소), 번역 결과 복사.
- 모델 3종 선택(Claude Sonnet 5.5 기본, Gemini 3.8 Flash, GPT-6 Luna), 분석 전 **예상 토큰·비용 표시**, 같은 논문의 모델별 결과를 나란히 보는 **결과 비교**.

**계정과 화면**
- 이메일·비밀번호 가입 후 **관리자 승인**을 받아야 쓸 수 있습니다. 관리자는 설정 화면에서 승인·거절하고, 새 신청은 "대기 N" 배지로 알립니다.
- 두 가지 화면 테마(학술용 남색 3열, 교육용 따뜻한 서재와 상단 4단계 표시). 선택은 이 브라우저에 기억합니다.
- 스플래시와 로그인을 한 화면으로 구성했습니다.

## 4. 기술 스택 및 아키텍처

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 화면 | 바닐라 JS + CSS (프레임워크 없음), 전역 `PN` 이름공간 | 외부 패키지 없이 `npm install` 없이 빌드·테스트. 단일 HTML 배포 요구와 맞음 |
| 빌드 | `scripts/build.mjs`: 여러 소스 파일을 `dist/index.html` 하나로 합치고 `public/`, `vendor/`를 복사 | PRD의 "단일 HTML 배포"와 DESIGN의 "테마별 CSS 분리"를 함께 만족 |

| AI | OpenRouter, 브라우저에서 직접 호출 | CORS 통과를 확인했고, 키가 중간 서버를 거치지 않음 |
| PDF 처리 | pdf.js 6.4.299를 `vendor/`에 포함(해시를 테스트로 고정), 웹 워커 | 본문은 브라우저 안에서만 추출 |
| 호스팅 | GitHub Pages + GitHub Actions(테스트 통과 후 배포) | 무료, 저장소와 같은 곳에서 관리 |
| 테스트 | Node 내장 `node --test`, 브라우저 점검은 Playwright와 axe-core | 순수 로직은 테스트 먼저, 화면은 가짜 응답으로 시험 |

**구조 요약**

```
브라우저(단일 HTML) ──┬─ Supabase Auth/DB (RLS, 공개용 publishable 키)
                      ├─ Edge Function pn-search-proxy ──┬─ arXiv (3초에 1번, 연결 1개)
                      │                                  └─ Semantic Scholar
                      └─ OpenRouter (사용자가 입력한 키, 탭 세션에만 보관)
```

| Semantic Scholar 검색·일괄 조회 | 키 없이 429, 일괄 조회는 POST 불허 | 중계 함수, 인용수 보강 방식 조정 |

## 6. 주요 의사결정과 이유

1. **검색은 Edge Function 중계, AI는 브라우저 직접 호출.** CORS 실측 결과를 근거로 필요한 곳(검색)에만 서버를 둡니다. OpenRouter 키는 서버를 거치지 않아 "키는 `openrouter.ai`로 가는 요청에만 쓴다"는 원칙이 그대로 지켜집니다.
2. **OpenRouter 키는 서버에 저장하지 않고 탭의 `sessionStorage`에만 둡니다.** 탭을 닫으면 사라집니다. 사용자가 직접 입력하며, 채팅에 붙여 넣지 않는 규칙을 둡니다.
3. **PDF 원본과 추출 본문은 저장하지 않습니다.** 사용자가 끌어다 놓은 파일을 브라우저 안에서만 처리하고, 저장되는 것은 논문 정보, 메모, AI 결과뿐입니다. 논문 행에는 허용 열 목록으로 PDF 본문이 들어갈 수 없게 했고 테스트로 고정했습니다.
4. **가입 승인 방식, 확인 메일 없음.** 관리자가 승인하기 전에는 RLS가 데이터 접근을 막습니다. 승인할 때 이메일을 확인합니다. 거절된 계정은 지우지 않고 거절 화면만 보여 주며, 새 신청 알림은 앱 안의 배지로만 합니다.
5. **기본 모델은 Claude Sonnet 5.5 유지.** 세 모델을 비교한 뒤 사용자가 결정했습니다. 중요한 논문은 Sonnet 5.5, 가볍게 보는 논문은 Gemini 3.8 Flash나 GPT-6 Luna를 씁니다.
6. **스플래시와 로그인을 한 화면으로.** 이미 로그인한 승인 계정은 로고만 약 1초 보이고 바로 넘어갑니다.
7. **소스는 여러 파일, 배포는 한 파일.** 개발 중에는 파일을 나누고 빌드가 합칩니다.
8. **약관을 코드와 테스트로 지킵니다.** arXiv는 3초에 한 번, 연결 하나로만 호출하고, 사용자를 알아볼 수 있는 User-Agent를 보냅니다. 이 규칙은 테스트가 고정합니다.
9. **서재 순서 저장 방식.** 끌어서 놓으면 전체 목록을 0부터 다시 번호 매기고 바뀐 행만 저장합니다. 번호가 없는 새 논문은 맨 앞에 둡니다. 고정한 카드와 고정하지 않은 카드는 서로 자리를 넘나들 수 없고, 고정한 카드는 어떤 정렬에서도 맨 위입니다. DB에는 `pinned`, `sort_index` 두 열을 더했습니다.
10. **git은 사용자가, 위험한 일은 확인 후.** 모든 git 작업은 사용자가 직접 하고, 외부 서비스에 쓰는 작업(마이그레이션, 배포)은 실행 전에 확인을 받습니다. 저장소가 public이라 `.gitignore`를 꼼꼼히 점검했습니다.

## 7. 문제 해결 기록

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 브라우저에서 arXiv·Semantic Scholar 호출이 막힘 | CORS 헤더 없음, POST 불허 | Edge Function 중계 도입 |
| education 로그인 화면의 로고 글씨가 어두운 이미지 위에서 안 보임 | 접근성 도구(axe)는 배경 이미지 위 글씨를 검사하지 못함 | 스플래시 전용 색 토큰(`--on-splash`)을 만들고 명암비 테스트에 추가 |
| 서재에 다녀온 뒤 4단계 표시가 1단계로 돌아감 | 서재에서 검색 화면으로 돌아오면 상세가 분석 모듈에서 떨어져 나감 | 검색 화면으로 돌아올 때마다 저장 표시를 다시 읽음 |
| 768px에서 고정 상단 막대가 본문을 가림 | 1080px 이하에서도 고정이었음 | 1080px 이하에서는 일반 배치 |
| academic 1366px에서 검색 버튼이 줄바꿈됨 | 막대가 좁음 | 1440px 이하에서는 화면 제목 글씨를 숨겨 한 줄로 맞춤 |
| 프리셋을 못 불러왔을 때도 "프리셋이 없습니다"라고 나옴 | 로드 실패와 빈 목록을 구분하지 않음 | 로드 실패 상태를 따로 두고 추가 버튼을 막음 |
| DB 오류 문구의 어색한 문법 | 동사별 조합 | `dbErrorMessage(error, what)`로 "{what}에 실패했습니다"로 통일 |
| Windows 줄바꿈이 pdf.js 해시를 바꿀 위험 | CRLF 변환 | `.gitattributes`로 LF 고정, `vendor/**`는 변환 제외 |
| 같은 URL로 `goto`해도 시험 페이지가 새로고침되지 않음(시험 도구) | 해시만 같아서 이동으로 처리 | `reload()` 사용 |
| 시험 중 끌어놓기가 엉뚱한 카드에 적용(시험 도구) | 대상 카드가 화면 밖이라 도구가 끌던 중 스크롤 | 창을 키워 모든 카드가 보이게 하고 재시험 |
| "초록 단계**을** 분석합니다" 조사 오류 | 변수 뒤 조사 고정 | 맞춤법 검사로 발견, "를"로 수정 |
| 셸·스크립트의 따옴표와 역슬래시 문제 | 중첩 인용 | 스크립트는 파일로 쓰고, 수정은 Edit 도구로 |

## 8. 보안/성능 고려사항

**보안** (Phase 5-A 점검 결과, `docs/phase5-checks.md`)
- 소스와 빌드 결과에서 키 패턴(OpenRouter 키, `service_role`, `sb_secret_`, JWT, 개인 키) 0건. 테스트가 검사합니다.
- OpenRouter 키는 `openrouter.ai` 요청의 Authorization 헤더에만 실립니다. URL, 본문, 화면, 쿠키, `localStorage`에는 없습니다.
- 모델과 논문의 글은 모두 `textContent`로 넣고(innerHTML 미사용), 외부 링크는 `safeUrl`과 `rel="noopener noreferrer"`를 씁니다.
- 콘텐츠 보안 정책(CSP): 연결 대상을 Supabase와 OpenRouter로 제한하고 허용 목록 밖 연결을 막습니다. 정책 내용은 테스트로 고정했습니다.
- 중계 함수는 로그인과 승인 확인, 출처 검사, 요청 크기·형식 검증을 하고 요청 내용을 로그에 남기지 않습니다. `service_role`은 쓰지 않습니다.
- RLS 시험 22개 항목 통과(롤백되는 시험, 잔여 데이터 0). `rls_auto_enable()` 실행 권한 회수 마이그레이션을 적용했습니다.
- 정적 파일의 외부 라이브러리는 버전 고정과 무결성 해시(SRI)를 씁니다.

**성능**
- 검색 결과 100개 렌더링: 화면 멈춤(long task) 0건. 같은 검색 재실행은 59ms(호출 0건).
- 151쪽·약 17만 토큰 PDF를 0.33초에 추출. 400쪽(약 53만 토큰) 분량의 제목 감지·번역 조각 나누기·비용 어림은 17ms 이하.

**접근성**
- 두 테마의 모든 색 조합이 명암비 4.5:1 이상(테스트). axe 점검으로 14개 화면 위반 0건, 서재 화면도 두 테마에서 0건.
- 키보드 이동과 포커스 표시, "본문으로 건너뛰기" 링크, 대화상자의 Esc 닫기와 포커스 복귀, 색만으로 뜻을 전달하지 않기.

## 10. 배포

- GitHub Actions(`.github/workflows/pages.yml`): `main`에 올리면 `npm test` → `npm run build` → 배포용 폴더 점검(필수 파일, 원본 PNG 부재, 비밀 값 패턴 검색) → GitHub Pages 배포. 테스트가 하나라도 실패하면 배포하지 않습니다.
- 프로젝트 사이트라 `/paper-note/` 하위 경로에서 열리므로 모든 자원 경로는 상대 경로입니다. 중계 함수의 `ALLOWED_ORIGINS`에는 출처만(`https://poguni.github.io`) 넣습니다.
- 배포 확인(2026-10-06): 자원 응답 정상, 4.5MB 원본 스플래시는 의도대로 404, 배포된 `index.html`이 로컬 빌드와 동일, 중계 함수가 배포 출처를 허용하고 다른 출처는 403, 로그인 없는 요청은 401.
- 새 DB 열(`pinned`, `sort_index`)은 마이그레이션으로 먼저 적용되어 이전 버전 앱에도 영향이 없습니다.

## 11. 알려진 한계

- **유출 비밀번호 보호 꺼짐**: Supabase Pro 플랜 이상의 기능이라 무료 플랜에서는 켤 수 없습니다. 위험을 수용하고, 최소 비밀번호 8자와 가입 승인 전 데이터 접근 차단으로 영향을 줄였습니다. 보안 점검의 마지막 경고 1건입니다.
- **서재 카드 끌기는 마우스 중심**: 터치 화면에서는 손잡이의 키보드 이동만 됩니다.
- **인용수**는 Semantic Scholar 값이라 일부는 "미확인"이거나 다른 서비스와 다를 수 있습니다. Semantic Scholar는 키 없이 호출 한도에 걸릴 수 있습니다(안내 문구로 알림).
- **스캔본 PDF**는 글자를 추출하지 못해 본문 단계를 쓸 수 없고 초록 단계만 가능합니다.
- **교육학 논문**은 arXiv에 거의 없어 Semantic Scholar 중심입니다(ERIC 어댑터는 확인하지 않음).
- **비밀번호 재설정 메일이 없습니다.** 관리자가 Supabase 대시보드에서 재설정합니다.
- 라이선스를 아직 정하지 않았습니다(저장소는 public).
- 성공 기준(분석 1건당 허용 비용, 검색부터 저장까지 걸리는 시간)을 아직 정하지 않았습니다.
- 모델 이름과 가격은 2026-10-05에 확인한 값이며 바뀔 수 있습니다.
